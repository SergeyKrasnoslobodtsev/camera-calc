# Правила текстов интерфейса

Правила для всех строк интерфейса калькулятора на русском и английском: подписи полей, кнопки,
заголовки, отчёт, предупреждения, подсказки «?», блок «Все формулы», встроенные шаблоны.
Новая строка добавляется в словарь только по этим правилам, а термины берутся из глоссария.

Источники:

- **EN** — [Microsoft Writing Style Guide](https://learn.microsoft.com/en-us/style-guide/welcome/):
  [Capitalization](https://learn.microsoft.com/en-us/style-guide/capitalization),
  [Numbers](https://learn.microsoft.com/en-us/style-guide/numbers),
  [Units of measure](https://learn.microsoft.com/en-us/style-guide/a-z-word-list-term-collections/term-collections/units-of-measure-terms),
  [Scannable content](https://learn.microsoft.com/en-us/style-guide/scannable-content/);
  для элементов интерфейса — [Writing style — Windows apps](https://learn.microsoft.com/en-us/windows/apps/design/style/writing-style).
- **RU** — [Microsoft Russian Localization Style Guide](https://aka.ms/russian-styleguide), разделы
  4.1.1 Abbreviations, 4.1.3 Capitalization, 4.1.7 Numbers, 4.1.10 Punctuation,
  4.1.13 Nonbreaking spaces, 5.4.2 Error messages.

!!! note "Тон"
    Руководства Microsoft рекомендуют разговорный, «тёплый» тон и местоимение «мы» от лица продукта.
    Калькулятор рассчитан на инженеров, поэтому от руководств берутся форма и единообразие
    (регистр, пунктуация, числа, единицы, построение сообщений), а тон выбран
    **нейтрально-технический**: без «мы», без оценок («отлично», «к сожалению»), без восклицательных знаков.

## 1. Общие правила

| № | Правило | Пример (RU / EN) |
| --- | --- | --- |
| 1.1 | Один термин — одно понятие во всём интерфейсе. Синонимы не используются, термины — только из глоссария. | «матрица», а не «матрица / сенсор» вперемешку |
| 1.2 | Главное — в начале строки. Без вводных фраз. | «Зона не помещается по ширине: …» / «Zone doesn't fit horizontally: …» |
| 1.3 | Регистр как в предложении: с прописной только первое слово и имена собственные (RU 4.1.3, EN Capitalization). | «Ширина зоны, м» / «Zone width, m» |
| 1.4 | Без произвольных сокращений. Сокращать можно, только когда не хватает места, и только общепринятые сокращения (RU 4.1.1). | «Количество», а не «Кол-во»; «Коэффициент качества», а не «Коэфф. качества» |
| 1.5 | Аббревиатуры из даташитов и стандартов (HFOV, NVDEC, FP16, DORI, PoE, ROI) не расшифровываются в подписи. Расшифровка даётся в подсказке «?» при первом упоминании. | — |

## 2. Элементы интерфейса

| Элемент | Правило | Пример (RU / EN) |
| --- | --- | --- |
| Подпись поля | Существительное или именная группа, единица через запятую. Точки нет. | «Высота камеры, м» / «Camera height, m» |
| Кнопка | Глагол действия, 1–3 слова. В RU — инфинитив или повелительное наклонение, одинаково по всему интерфейсу. Точки нет. | «Добавить камеру» / «Add camera» |
| Кнопка или ссылка добавления в компактном месте | Знак «+» вместо глагола «Добавить» и существительное. | «+ Объект» / «+ Object» |
| Заголовок блока | Именная группа, регистр как в предложении. Вопросы и разговорные формулировки не используются. | «Нагрузка на GPU» вместо «Что нагружается» |
| Пункт списка, вариант выбора | Именная группа или прилагательное. Точки нет. | «Весь кадр» / «Full frame» |
| Подсказка «?» | Законченные предложения с точкой. Сначала что это, потом откуда взять значение, потом типичные значения. | — |
| Предупреждение в отчёте | Что случилось → чем это грозит → что сделать. Законченные предложения с точкой. Пользователя в ошибке не обвиняем (RU 4.1.14, пассивные и безличные конструкции). | «Зона не помещается по ширине: … Поднимите камеру или уменьшите ширину зоны.» |
| Пустое состояние | Что нужно сделать, чтобы появился результат, в одном предложении. | «Добавьте камеры и объекты с моделями.» |
| aria-label | Как подпись поля: коротко, без точки, тот же термин, что и в видимом тексте. | «Удалить объект» / «Delete object» |

Шаблоны сообщений об ошибках для RU (раздел 5.4.2): «Не удалось …», «Не удаётся …», «… недоступен».
Слово «нельзя» не используется.

## 3. Числа и единицы

| № | Правило | RU | EN |
| --- | --- | --- | --- |
| 3.1 | Десятичный разделитель | `0,85` | `0.85` |
| 3.2 | Разделитель тысяч: с 4 знаков, у пикселей — с 5 | `13 250` (неразрывный пробел); `1920 × 1080` | `13,250`; `1920 × 1080` |
| 3.3 | Между числом и единицей — неразрывный пробел (RU 4.1.13, EN Units of measure) | `2,8 мм` | `2.8 mm` |
| 3.4 | Диапазон — короткое тире (–) без пробелов (RU 4.1.10, EN Numbers: в UI) | `2,8–12 мм` | `2.8–12 mm` |
| 3.5 | Размеры и разрешения — знак × с пробелами | `2560 × 1440` | `2560 × 1440` |
| 3.6 | Числа — цифрами, даже меньше 10, если с единицей измерения | `5 кадр/с` | `5 fps` |
| 3.7 | Отрицательные числа — со знаком минус (U+2212) | `−0,5 м` | `−0.5 m` |
| 3.8 | Проценты в интерфейсе — цифра и знак % без пробела (решение проекта: в подписях мало места) | `20%` | `20%` |
| 3.9 | Валюта — знак перед числом | `$13 250` | `$13,250` |

Единицы:

| Величина | RU | EN | Примечание |
| --- | --- | --- | --- |
| длина | м, см, мм, мкм | m, cm, mm, µm | |
| пиксели | px | px | EN-руководство не рекомендует *px* для разрешения камеры. В подписях и единицах `px` оставлен из-за нехватки места, в тексте подсказок EN — *pixels* |
| плотность пикселей | px/м | px/m | |
| частота кадров | кадр/с | fps | вместо `к/с`: это сокращение не входит в список общепринятых (RU 4.1.1) |
| угол | ° | ° | |
| поток | Мбит/с, Гбит/с | Mbps, Gbps | |
| память | ГБ | GB | |
| мощность | Вт | W | |
| время | с, сут. | s, days | |

## 4. Пунктуация

| № | Правило |
| --- | --- |
| 4.1 | Тире (—) в RU — только по правилам грамматики, с пробелами. Дефис вместо тире не ставится (RU 4.1.10). |
| 4.2 | Многоточие — один символ (…, U+2026) сразу после текста. |
| 4.3 | Точка с запятой не используется: лучше два коротких предложения (RU 4.1.10). Исключение — разделитель элементов перечня, в которых уже есть запятые, в том числе десятичные: «Деталь — 10,5 × 3,2 px; Гайка — 4,1 × 2,0 px». |
| 4.4 | После двоеточия в RU — строчная буква (RU 4.1.10). |
| 4.5 | Восклицательные знаки не используются. |
| 4.6 | Названия элементов интерфейса в тексте берутся в кавычки (RU 4.1.10): в RU — «ёлочки», в EN — прямые `"…"`. |

!!! warning "Отступление от RU-руководства: кавычки"
    RU-руководство Microsoft требует в интерфейсе прямые кавычки `"Готово"`, а «ёлочки» оставляет
    для печатной документации. В калькуляторе сохранены «ёлочки» — традиционная русская типографика,
    которой интерфейс следовал и раньше.

## 6. Примеры «было → стало»

| Было | Стало (RU) | EN | Правило |

| Коэфф. качества | Коэффициент качества | Quality factor | 1.4 |
| Что нагружается | Нагрузка на GPU | GPU load | 2, заголовок |
| Что ищем и чем | Объекты и модели | Objects and models | 2, заголовок |
| Фокусное, мм | Фокусное расстояние, мм | Focal length, mm | глоссарий |
