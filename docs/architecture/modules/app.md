# Модуль app

Состояние приложения, действия над ним, пересчёт результатов, сохранение, загрузка, импорт и экспорт. Модуль не обращается к DOM и не знает текстов интерфейса. Из других модулей он импортирует только `domain`. Решения — в [`../decisions/app.md`](../decisions/app.md).

## Состав

| Файл | Что внутри |
|---|---|
| `store.ts` | Объект состояния `state`, результаты расчёта `computed`, подписка `subscribe` (возвращает отписку), действия и выборки (`activeType`, `allGpus`, `cameraById` и т. п.) |
| `persistence.ts` | Сохранение в `localStorage`, загрузка `loadSaved`, импорт `importText`, экспорт `exportText`, слежение за другими вкладками |
| `examples.ts` | Начальные данные: встроенный пример, новый объект `NEW_OBJECT`, значения полей типа и параметров системы по умолчанию, `uid` |

```mermaid
flowchart LR
    ui[ui] -- действие --> store[store.ts]
    store -- parse*, computeType, computeSystem, systemTotals --> domain[(domain)]
    store -- уведомление --> ui
    store -- уведомление --> main[точка входа]
    main -- save --> persistence[persistence.ts]
    main -- loadSaved → restore --> store
    persistence -- parse* --> domain
    examples[examples.ts] --> store
    examples --> persistence
```

## Состояние

Состояние одно на страницу (`state` в `store.ts`). Меняют его только действия из `store.ts`.

| Поле | Что хранит |
|---|---|
| `cameraTypes`, `activeTypeId` | Типы камер черновиком и id активного типа |
| `customGpus`, `customCameras`, `customObjects`, `customModels` | Свои шаблоны: видеокарты, камеры, объекты детекции, модели — записи, прошедшие разбор |
| `gpuPrices`, `gpuEnabled` | Правки цен GPU как введены и участие в подборе по id GPU |
| `system` | Параметры системы черновиком: `efficiency`, `reserve`, `archiveDays`, `gpu`, `gpuCount` |
| `light` | Светлая тема |

**Черновик.** Поля типа камер, объектов и параметров системы хранятся так, как их ввёл пользователь: строками из полей формы или числами из шаблона. Перед расчётом черновик проходит через `parseCameraType` и `parseSystemSettings`. Сохраняется тоже черновик, поэтому после перезагрузки в поле возвращается введённая строка, даже недопустимая.

**Объект типа камер ссылается на шаблоны.** Черновик объекта (`ObjectDraft`) хранит, что ищет — `target`, id объекта детекции, — и какой моделью — `model`, id модели; рядом подача, вход модели и перекрытие. Габаритов, порога и своего названия у него нет. Перед разбором `withTargets(type, detectionObjects)` подставляет в каждый объект название (`name` или `nameKey`), габариты и порог его объекта детекции, и расчёт получает `SceneObject` целиком. Поэтому правка своего объекта детекции меняет расчёт всех объектов, которые на него ссылаются. Почему ссылка, а не копия, — в [`../decisions/app.md`](../decisions/app.md#объект-типа-ссылается-на-объект-детекции-по-id). Объекты детекции — встроенные `BUILTIN_DETECTION_OBJECTS` и свои `customObjects`, выборка `allDetectionObjects`.

**Названия.** У встроенной записи (пример, объект детекции, камера из каталога) есть ключ словаря `nameKey`, а `name` пустое. Своё название лежит в `name`, и тогда `nameKey` нет. Если пользователь меняет встроенное название, действие убирает `nameKey`. Текст для показа даёт `displayName` из `i18n`: по `nameKey` на текущем языке, иначе `name`.

## Действие и пересчёт

```mermaid
sequenceDiagram
    participant U as ui
    participant S as store.ts
    participant D as domain
    U->>S: действие, например updateObject(0, "feed", "tiles")
    S->>S: изменить state
    S->>D: parse* черновиков с подставленными объектами детекции, computeType, computeSystem, systemTotals
    D-->>S: результаты
    S->>S: computed = результаты
    S-->>U: подписчики: отрисовка, сохранение
```

Пересчитываются все результаты после каждого действия (`computed`):

| Поле `computed` | Что содержит |
|---|---|
| `results` | Результат по каждому типу в порядке `state.cameraTypes`. Если черновик не прошёл разбор — `{ ok: false, type, count }`, где `type` — черновик, а `count` — число камер, если оно допустимо, иначе 0 |
| `system` | Подбор GPU или `null`, если в параметрах системы или в цене карты ошибка |
| `totals` | Итоги системы; при ошибке в параметрах глубина архива — `NaN` |

Действие сохраняет связность ссылок в состоянии: если удалить свою карту, свои модели, замеренные на ней, переходят на RTX 5090, а выбор карты переключается на «авто». Если удалить камеру, типы с ней переходят на ручную матрицу. Если удалить свою модель, объекты с ней переходят на YOLO26s. Если удалить свой объект детекции, объекты типов с ним переходят на «Человек» (`person`).

## Сохранение, загрузка, импорт

| Операция | Правило |
|---|---|
| Сохранение | После каждого действия точка входа вызывает `save(state)`, данные лежат в `localStorage` под ключом `camcalc5`. Если данные изменили в другой вкладке, сохранение не выполняется, и `save` возвращает `false` |
| Загрузка | `loadSaved()` разбирает записи сохранения функциями `parse*` и пропускает те, что не прошли разбор. Черновик типа и параметров с недопустимым числом принимается (`onlyValueErrors`). Тип разбирается с подставленными объектами детекции, а в состояние попадает черновиком со ссылками. Ссылки на то, чего нет, заменяются значением по умолчанию: объект детекции — «Человек», модель объекта — YOLO26s, карта — «авто», число карт не из списка — «авто» |
| Импорт | `importText(text)` отклоняет файл целиком (`"badFile"`), если в нём нет нужных частей (в том числе списков `customModels` и `customObjects`) или хоть одна запись не прошла разбор. Принятый файл записывается в `localStorage` (`"ok"`), после чего интерфейс перезагружает страницу |
| Экспорт | `exportText(state)` — то же, что сохраняется, с отступами |

Старые сохранения с десятичной запятой (`"1,5"`) при загрузке и импорте приводятся к виду `"1.5"`. Сохранения под прежним ключом `camcalc4` и файлы экспорта со списком `customDetectors` не переносятся, см. [`../decisions/app.md`](../decisions/app.md#старые-сохранения-не-переносятся).

## Соглашения

- **Изменения только через действия.** Вне `src/app/` поля `state` не присваиваются. Интерфейс читает `state` и `computed` и вызывает действия.
- **Отрисовка не зависит от порядка.** Подписчик рисует результаты. Функции, которые пересоздают разметку (`writeForm`, `renderObjects`), сами дорисовывают в неё результат из `computed`, поэтому их можно вызывать до уведомления или после.
- **Коды вместо текстов.** `importText` возвращает код (`"ok"`, `"badFile"`, `"saveFail"`), а текст сообщения выбирает интерфейс.

## Проверки

| Тест | Что проверяет |
|---|---|
| `tests/page/` | Введённая строка сохраняется после перезагрузки; файл с недопустимой записью не импортируется, и сохранение не меняется; сохранение с недопустимой записью загружается без неё; недопустимые выбор карты и число карт при загрузке заменяются на «авто»; копия типа |
| `tests/golden/` | Результаты расчёта на странице совпадают с `tests/golden/golden.txt` |

Отсутствие присваиваний полям состояния вне `src/app/` проверяется поиском:

```bash
grep -rnE "(state|type|obj|object|detector|gpu|camera|inputs)(\.[A-Za-z_]+|\[[^]]+\])+ *(=[^=>]|\+\+|--|\+=|-=)|\.(push|splice|pop|shift|unshift|sort|reverse)\(|delete [a-z]" src/ui src/main.tsx
```

Он находит только сортировку и `push` локальных массивов при отрисовке кольца в `src/ui/system-panel.ts`.
