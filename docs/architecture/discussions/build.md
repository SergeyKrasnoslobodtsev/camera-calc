## 2026-10-29 — сборка и линтер для интерфейса на React

**Статус:** принято → [`../decisions/build.md`](../decisions/build.md#сборка-на-vite-в-один-html), [`../decisions/build.md`](../decisions/build.md#линтер-oxlint)

**Вопрос.** Интерфейс переходит на React (#65). Чем собирать `.tsx`: своим `build.ts` на esbuild или Vite. Каким линтером проверять правила хуков React.

**Варианты.**

- Сборка: `build.ts` на esbuild — esbuild собирает JSX сам, сборка остаётся своим скриптом. Vite с `vite-plugin-singlefile` — распространённый сборщик для React-проектов, даёт сервер разработки; вставку формул нужно перенести в конфигурацию Vite.
- Линтер: ESLint с `typescript-eslint` и `eslint-plugin-react-hooks`; Oxlint, в котором правила хуков встроены.

**Условия замера.** Vite 8.3.5, `@vitejs/plugin-react` 6.1.2, `vite-plugin-singlefile` 2.3.4, TypeScript 7.0.2, jsdom 24, Node v26.12.1, macOS. Проверки: `npm test`, открытие `dist/index.html` по `file://` в Chrome 156 без окна (`--headless=new --dump-dom`).

**Результат.**

- Vite собирает страницу в один файл `dist/index.html`. Внешние ссылки — только шрифты Google Fonts, как раньше. Из `file://` Chrome отрисовал вкладки и вердикт, ошибок JavaScript в логе нет.
- Скрипт Vite встраивает как `<script type="module">`. jsdom 24 такой скрипт не выполняет: без доработки тестов страница в тесте пустая. Тесты добавляют текст скрипта в конец страницы обычным `<script>` (`tests/page.js`) — браузер тоже выполняет модульный скрипт после разбора страницы.
- React отрисовывает не сразу, поэтому тесты ждут отрисовку (`settle` в `tests/page.js`). Одного `setTimeout` после загрузки мало: первую отрисовку React планирует из микрозадачи, и его задача встаёт в очередь позже задачи теста. Это нашлось потому, что вкладки в тесте оказались пустыми, а проверка «example names follow lang» всё равно прошла.
- `typescript-eslint` 8.72.1 требует `typescript` версии `>=4.8.4 <6.1.0`. В пакете TypeScript 7.0.2 в `lib/` только `tsc.js` и `getExePath.js` — JavaScript API, на котором работает `typescript-eslint`, нет.
- Oxlint 1.90.0 не зависит от пакета `typescript`. На пробном компоненте правило `rules-of-hooks` дало ошибку на условный `useState`, `exhaustive-deps` — предупреждение на пропущенную зависимость `useEffect`. На текущем коде — 12 замечаний категории `correctness`, все в коде до перехода на React (`no-unused-vars`, `no-unused-expressions`, `no-thenable`).

**Вывод.** Владелец выбрал Vite и Oxlint, имя страницы `dist/index.html` — для GitHub Pages (#66).

## 2026-10-28 — как проверять типы сущностей

**Статус:** принято → [`../decisions/build.md`](../decisions/build.md#typescript-и-проверка-типов-tsc)

**Вопрос.** Поля сущностей нигде не описаны целиком. Нужно описать их в одном месте и проверять использование до запуска.

**Варианты.**

- Без типов, только функции разбора и тесты. Зависимостей нет, но ошибка в имени поля находится только тестом или в браузере.
- JSDoc (`@typedef`) и `// @ts-check`, проверка `tsc --noEmit`. Код остаётся на JavaScript, проверку можно включать по файлу. Нужна зависимость `typescript`.
- TypeScript (`.ts`). Самая короткая запись типов, esbuild собирает `.ts` без отдельного шага компиляции. Проверка типов идёт через `tsc`, как и для JSDoc.

**Гипотеза.** Обоим вариантам с проверкой нужен `tsc`. Значит, по правилу выбора инструментов TypeScript проще JSDoc, если Node запускает тесты из `.ts` без своей сборки.

**Условия замера.** Временный файл `gpu.ts` с интерфейсом и функцией и тест `gpu.test.ts` на `node:test`. Запуск `node --test gpu.test.ts`, Node v26.12.1, macOS, без флагов и без `package.json`.

**Результат.** Тест прошёл: 1 из 1, код выхода 0.

**Вывод.** Берём TypeScript → [`../decisions/build.md`](../decisions/build.md#typescript-и-проверка-типов-tsc). Ловит ли `tsc` ошибки в полях сущностей на коде проекта, не проверено.

**Дальше.** При подключении `tsc` убедиться, что он падает на опечатке в имени поля сущности.

**Проверка при подключении (#46).** TypeScript 7.0.2, `@types/node` 26.6.6, Node v26.12.1, macOS. Проверяются `build.ts` и `src/**/*.ts`; файлов `.ts` в `src/` пока нет.

- Опечатка `outputFiles[0].txt` вместо `.text` в `build.ts`: `npm test` упал на `tsc` с `TS2551: Property 'txt' does not exist on type 'OutputFile'`, код выхода 1.
- Без `"types": ["node"]` в `tsconfig.json` `tsc` не находит `node:fs` (`TS2591`): TypeScript 7 не подключает типы из `@types` сам.
- Без опечатки `npm test` прошёл; `tests/golden.txt` не изменился (MD5 `4aca6d63376b6332c8e7cc1633c40bd4`).
- Опечатку в поле сущности проекта не проверяли: сущности ещё на JavaScript.

**Найдено при подключении.** esbuild сам читает `tsconfig.json` и из-за `strict: true` начинает собранный скрипт с `"use strict"`; других отличий в `dist/camera-calc.html` нет. `npm test` прошёл, страница из `file://` в Chrome без окна (`--headless=new --dump-dom`) показала вердикт, ошибок JavaScript в логе нет. Владелец выбрал оставить строгий режим, а не отключать чтение `tsconfig.json` в `build.ts`: модули по стандарту строгие, а формат `iife` это терял.

## 2026-10-28 — каким сборщиком собирать модули в один HTML

**Статус:** принято → [`../decisions/build.md`](../decisions/build.md#сборка-модулей-esbuild-в-один-html)

**Вопрос.** Нужен сборщик, который соберёт ES-модули в один скрипт для `dist/camera-calc.html`. Страница должна открываться из файла без сервера.

**Варианты.**

- esbuild: формат `iife` даёт один скрипт. Сборочный скрипт на Node вставляет его в разметку, как `build.py` сейчас вставляет склеенные файлы. Одна зависимость, Python больше не нужен.
- Vite с плагином `vite-plugin-singlefile`: собирает HTML со встроенными скриптами и стилями, даёт сервер разработки с перезагрузкой. Больше зависимостей. Разметку и вставку формул пришлось бы переносить в конфигурацию Vite.

**Гипотеза.** esbuild меняет меньше: остаётся порядок работы «правка → сборка → открыть файл», а сборочный скрипт короткий.

**Условия замера.** Файлы `src/js/` переведены на `import`/`export` без перестройки (#32). esbuild 0.28.2, формат `iife`, точка входа `src/js/init.js`, сборочный скрипт `build.ts` на Node v26.12.1, macOS. Проверки: `npm test` (smoke и тест-эталон), открытие `dist/camera-calc.html` по `file://` в Chrome без окна (`--headless=new --dump-dom`).

**Результат.**

- `npm test` прошёл; `tests/golden.txt` не изменился (MD5 `4aca6d63376b6332c8e7cc1633c40bd4` до и после).
- Страница из `file://` посчитала систему и вердикт, ошибок JavaScript в логе Chrome нет.
- `build.ts` занимает 38 строк после Prettier, `build.py` занимал 17 строк.
- Vite с `vite-plugin-singlefile` не собирали.

**Вывод.** Берём esbuild → [`../decisions/build.md`](../decisions/build.md#сборка-модулей-esbuild-в-один-html).

**Найдено при переходе.** Порядок выполнения модулей теперь задают `import`, и круговые импорты его меняют: `system-ui.js` при загрузке читает `OBJECT_PRESETS` из `state.js`, а `state.js` через `objects.js` ведёт обратно к `system-ui.js`. Поэтому `init.js` импортирует `system-ui.js` раньше `state.js`. Тест-эталон заметит, если порядок сломается.
