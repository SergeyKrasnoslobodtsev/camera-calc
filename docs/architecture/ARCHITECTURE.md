# Архитектура

Калькулятор — одна HTML-страница без сервера. По параметрам типов камер он считает геометрию кадра, плотность пикселей и размер объекта на входе модели, а по нагрузке подбирает GPU. Код делится на ядро расчёта и слои вокруг него: состояние, тексты, интерфейс.

!!! warning "Целевая структура"
    Ниже описана структура, к которой переходит код (задача #28). Сейчас код лежит в `src/js/` файлами с числовыми префиксами и склеивается в один `<script>` в порядке имён (`build.py`). Столбец «Сейчас» в таблице модулей показывает, где код находится до перехода. Когда переход закончится, столбец нужно удалить.

## Модули

| Модуль | Папка | Отвечает за | Сейчас |
|---|---|---|---|
| `domain` | `src/domain/` | Расчёт и сущности: справочники, разбор и проверка данных, расчёт типа камер, подачи в модель, вердикта, подбора GPU, сети и архива. Без DOM, без текстов, без `localStorage` | `04-compute-type.js`, `computeSystem` в `05-system-ui.js`, справочники в `01-data.js` и `03-objects.js`, итоги внутри `renderSystem` |
| `app` | `src/app/` | Состояние приложения в одном месте, действия над ним, пересчёт при изменении, сохранение, загрузка, импорт и экспорт | глобальные переменные в `01-data.js`, `02-state.js`, `03-objects.js`; `save`, `load`, `importText`, `snapshot` в `05-system-ui.js` |
| `i18n` | `src/i18n/` | Словари RU и EN, функция `t()`, единицы измерения, форматирование чисел, перевод кодов из `domain` в текст | `00-i18n.js`, `formatNumber` в `01-data.js`, тексты внутри `computeType` и `computeSystem` |
| `ui` | `src/ui/` | DOM: формы, карточки объектов, результат, панель системы, экраны шаблонов, схема SVG, текстовый отчёт, подсказки, уведомления, тема, маршрутизация | `02-state.js` (форма), `03-objects.js`, `05-system-ui.js`, `06-draw-side.js`, `08-popover.js` |
| точка входа | `src/main.ts` | Создаёт состояние, загружает сохранение, подключает интерфейс | `09-init.js` |
| `build` | `build.ts`, `tests/` | Сборка модулей в один HTML-файл `dist/camera-calc.html`, проверки: тесты, эталон, типы | `build.py`, `tests/` |

Разметка и CSS остаются в `src/layout.html`, текст блока «Все формулы» — в `src/formulas.html` и `src/formulas.en.html`.

## Связи

```mermaid
flowchart LR
    main[main.ts] --> ui
    main --> app
    ui --> app
    ui --> i18n
    ui --> domain
    app --> domain
```

Стрелка значит «импортирует». Зависимости идут в одну сторону. `domain` и `i18n` не импортируют ничего из остальных модулей. `app` не знает про DOM и тексты. Связывает коды из `domain` с текстами из `i18n` только `ui`.

## Поток данных

```mermaid
sequenceDiagram
    participant U as ui
    participant A as app
    participant D as domain
    participant T as i18n
    U->>A: действие (изменено поле, добавлен GPU)
    A->>D: parse* черновика → сущности
    A->>D: расчёт по сущностям
    D-->>A: результат: числа и коды
    A-->>U: уведомление: состояние изменилось
    U->>T: коды и числа → текст
    U->>U: отрисовка
```

Сохранение, загрузка и импорт проходят через те же функции `parse*`, что и формы.

## Сквозные правила

- **Сырые данные проверяются на входе.** Форма, файл импорта и `localStorage` — это границы. Данные с них проходят через функции разбора сущности (`parseGpu`, `parseCamera` и т. д.) из `domain`. Для каждой сущности функция одна, и все границы пользуются ею. Внутрь попадают только проверенные значения с правильными типами.
- **`domain` возвращает коды, а не тексты.** Статус, заметки и причины ошибок передаются как код и значения, например `{ code: "zoneWidth", values: { have, need } }`. Текст собирает `i18n` по запросу `ui`. Встроенные названия (примеры, камеры из каталога) хранятся в `domain` как ключ, а отображаемое имя даёт `i18n`.
- **Глобальных переменных между модулями нет.** Связи между модулями видны только через `import` и `export`. Изменяемое состояние есть только в `app`.
- **Имена файлов в kebab-case, по назначению.** Числовых префиксов нет, порядок задают `import`.

## Выбор инструментов

Инструмент (сборщик, язык, библиотека, фреймворк) берётся, если выполнены два условия:

1. Калькулятор остаётся одной HTML-страницей, которая открывается из файла без сервера.
2. Инструмент упрощает код или работу с ним и уменьшает накладные расходы: меньше своего кода, языков, ручных шагов. Этот выигрыш должен перевешивать цену новой зависимости.

Правило задано владельцем проекта 2026-10-28. Конкретный выбор записывается в `decisions/` модуля вместе с тем, чем он проверен.
